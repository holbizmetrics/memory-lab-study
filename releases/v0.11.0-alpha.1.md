# Memory Lab Study v0.11.0-alpha.1

PATCH DICE generates starting sounds from constrained oscillator, filter,
envelope and motion ranges. Open DICE below OUTPUT, choose section locks and
ROLL NEW SOUND. UNDO ROLL restores the complete patch from before the latest
roll; SAVE keeps a result as an ordinary .mlpatch file.

Four locks preserve OSC, FILTER, ENVELOPES and MOTION parameter groups. Output,
both drives, memory depth/recovery, arp settings, oscillator phase reset and
fallback BPM are always preserved. When all sections are locked, rolling is
disabled. Locks and one-roll undo survive editor close/reopen within an instance.
Sound changes after a roll invalidate undo so it cannot overwrite later edits.
There is no multi-step undo or redo, and UI locks/history are not saved in
patches or projects. A new instance starts unlocked.

Compatibility: unchanged production DSP, factory sound, 46 host IDs/order and
schema-7 patch format. Existing patches and project-state migration remain as
before. New generated patch files can be read by 0.10. No randomizer controls
are added to host sound parameters. Random generation/history runs on the UI
thread as an explicit action; opening the editor or dice page does not roll.

Validation: Windows VST3/standalone built; all eight plugin CTest checks passed.
Randomizer checks cover all 16 lock combinations with no writes to protected or
locked controls, nondefault protected settings, reproducible seeded rolls,
latest-roll undo, invalidation after later edits, schema roundtrip, UI actions,
session persistence and all-locked history preservation. Thirty-two eight-voice
48 kHz drive-bypassed fixtures were finite/audible, with maximum peak 0.491786;
this is fixture evidence, not a universal headroom guarantee. The suite also
covers stable IDs/gestures, patch/clock/waveform migration, 160 page switches
without sound-parameter writes, and isolated editor lifecycle.

Actual VST3 scan/load/MIDI/arp/state/release/reload passed. Default audio remains
byte-identical to the prior verified fixture; a controlled clocked-patch render
is byte-identical to 0.10. Four seeded generated patches were saved and rendered
through the actual module. Normal/compact dice-page snapshots were inspected.
Examples are generated by plugin/study-dice.py into outputs/dice-study-1/.

Listening status: Holger confirmed 0.10's CLOCK movement works musically and
reports saving a clocked patch. Musical approval of 0.11's generated sounds is
pending. No hardware Relic equivalence is claimed; dice is a software extension.

Limits: rolls vary in loudness and are not normalized. Preserved drive/output or
locked settings can still produce distortion, silence or excessive level. Locks
preserve base controls, not audible modulation from other unlocked sections.
Existing held-note envelopes stay latched; release and play new notes after a
roll. Conflicting host automation can override generated values. Full FL undo/
automation/project reload and live folder-persistence verification remain open.
Local updates require closed hosts and a hash-verified backup. Source-only
prerelease with no binary assets, pending distribution licensing.
